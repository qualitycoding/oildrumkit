# Oil Drum Kit

**Oil Drum Kit** is a portable, modal-synthesis drum plugin built with C++ and JUCE. Rather than modeling a traditional harmonic drum membrane, this engine specifically simulates the raw, harsh, and industrial resonance of struck sheet steel and oil barrels.

---

## Sound Model & Features

The engine is a **physical-modelling** design (rewritten from an earlier sine + filtered-noise synth):

- **Modal synthesis of a struck steel drum.** Each hit is a bank of damped 2-pole resonators, one per
  structural mode, excited by a single Hertz-type contact-force pulse. Nothing is driven by continuous noise.
- **Mode data from physics** (`Source/ModeTables.h`, generated by `Tools/modes.py`): the struck lid is a clamped
  circular plate (exact Bessel eigenvalues, verified against published values), the side wall a Donnell thin shell,
  plus closed-cylinder air modes. Frequencies are ratios of each drum's tunable fundamental.
- **Strike position, radiation and stereo.** Modal weights come from the mode shape at a randomised strike point,
  a radiation-efficiency law, and a cos/sin split of non-axisymmetric modes (which produces beating). Each mode has
  its own left/right gain, so the kit is naturally decorrelated in stereo.
- **Frequency-dependent damping** (`sigma = sigma0 + pi*eta*f + sigma2*f^2`), so highs die much faster than lows.
- **Snare wires** as stochastic micro-impacts driven by shell amplitude; **cymbals/hats** as a dense modal bank plus a
  decaying-noise residual above the last mode, with a mild nonlinearity.
- **Interchangeable hammers** (Metal / Wood / Rubber) change the contact time (bright vs dull) and the contact "tick".
- **Extra parameters:** Strike Position, Damping, Room. Small built-in room and a soft limiter.
- 15 GM-mapped instruments, real-time safe (no allocation in `trigger()`/`process()`), header-only engine
  (`Source/DrumEngine.h`) with no JUCE dependency.

**Status / honesty:** the physics is anchored to a published plate table and to measured 55-gal drum-lid
frequencies, but *no listening test and no comparison with real recordings has been done*. Every number, its
source and its confidence level is in [`Renders/RESEARCH.md`](Renders/RESEARCH.md). Voicing is meant to be tuned by ear
in `Tools/voicing.json`.

## Regenerating the tables / voicing

```
python3 Tools/modes.py verify      # solver checks against published values
python3 Tools/modes.py generate    # writes Source/ModeTables.h and Source/Voicing.h
python3 Tools/calibrate.py         # sets per-instrument output gain (needs g++)
python3 Tools/modes.py report      # per-instrument mode counts, ranges, T60
```

## Getting Started

To compile the plugin from source, you will need a C++17 compatible compiler and CMake.

*   Clone the repository containing the source code.
*   Configure the project using CMake, ensuring JUCE is properly linked or included via `add_subdirectory`.
*   Build the VST3 or Standalone target using your preferred IDE or command-line build tool.
